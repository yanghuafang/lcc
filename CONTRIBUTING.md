# Contributing to `lcc`

Thanks for your interest in `lcc`, a teaching C compiler built on **flex**, **bison**, and **LLVM 20**. Contributions of all sizes are welcome: bug fixes, new test programs, clearer docs, and milestone work from the [learning plan](docs/LearningPlan.md).

Because `lcc` is primarily a **learning resource**, clarity and small, reviewable changes matter more than large features.

## Ways to contribute

- **Fix a bug** in the front-end, middle-end, or back-end — [docs/Architecture.md](docs/Architecture.md) maps `src/` files to responsibilities.
- **Add a test** that covers a supported language feature (see below).
- **Improve documentation** in `docs/`, or add code comments that explain *why*.
- **Work a milestone** or one of the unscheduled [future directions](docs/LearningPlan.md#future-directions-no-milestones).

## Prerequisites

`lcc` targets **macOS** (Homebrew) and **Ubuntu 24.04 / 26.04**. You need LLVM 20, flex, bison, argparse, graphviz, CMake 3.22+, a C++17 compiler, and a system linker (`clang` or `gcc`).

Install dependencies with the helper scripts:

```bash
cd scripts
./install-deps-macos.sh     # macOS
./install-deps-ubuntu.sh    # Ubuntu 24.04 / 26.04
```

See [docs/Install.md](docs/Install.md) for details and manual CMake options.

## Build

```bash
cd scripts
./build-lcc.sh
```

The binary is written to `../../lcc-build/lcc` (a sibling of the repo, kept out of the source tree).

## Test

Every change must keep the full regression suite green. From `scripts/`:

```bash
./compile-tests.sh && ./link-tests.sh && ./run-tests.sh
```

Each step accepts a single file name so you can iterate quickly:

```bash
./compile-tests.sh 25.quick_sort.c
./link-tests.sh 25.quick_sort.c
./run-tests.sh 25.quick_sort.c
```

`compile-tests.sh` defaults to debug mode (`-g -O0`); pass `--release` for `-O2`.

CI (GitHub Actions) also runs these smoke checks on every push and pull request against Ubuntu 24.04 / 26.04 and macOS — run them locally before submitting:

```bash
./check-debug-info.sh          # DWARF present with -g
./check-asm-smoke.sh           # -S emits assembly
./check-machine-pass-smoke.sh  # -machine-stats leaves the object byte-identical (M17)
./bench.sh --smoke             # benchmarks compile/link/run (no timing gate)
```

Optional IR regression check against the committed goldens: `./check-ir-opt.sh` (see [docs/Testing.md](docs/Testing.md)).

## Adding a test

Test programs live in `tests/` and follow the naming pattern `N.short_name.c`.

1. Create `tests/N.short_name.c`. It should exercise one feature and self-check, printing `N.short_name.c PASS` on success (or `... FAIL`) and returning non-zero on failure. Because there is no preprocessor, declare any libc helpers manually (e.g. `int printf(char*, ...);`) — see [docs/Language.md](docs/Language.md).
2. Register it by adding the file name to the `tests=( … )` array in [`scripts/tests-compile-link-run.sh`](scripts/tests-compile-link-run.sh).
3. Run the suite. Compilation regenerates the golden artifacts under `debug/` (`.pre` / `.post` / final `.ll`, `.s`). Commit the goldens that correspond to your new test. AST graphs are not generated per test — they come from the assertion-free fixtures in `tests/graphs/`, which render into `debug/graphs/`; see [docs/Testing.md](docs/Testing.md#ast-graphs).

Use an existing test such as [`tests/25.quick_sort.c`](tests/25.quick_sort.c) as a template.

## Coding style

- **C++17**, formatted with `clang-format` using the repo's [`.clang-format`](.clang-format) (Google base style, 2-space indent, 80-column limit).
- Two scripts enforce this, and CI runs both — run them before committing:

  ```bash
  ./scripts/format.sh   # clang-format + strip trailing whitespace
  ./scripts/tidy.sh     # clang-tidy; --fix applies what it can
  ```

  `format.sh` also covers `Lexer.l` / `Parser.y`, which clang-format cannot parse. Both skip `src/generated/`; never format flex/bison output, since the next build reverts it and the diff is thousands of phantom lines.
- The clang-tidy check list in [`.clang-tidy`](.clang-tidy) is curated, not the full upstream set. Each disabled family carries the reason it was disabled — if a check would help, re-argue it there rather than silencing findings case by case.
- Prefer small, focused changes — **one idea per pull request**.
- Comments should explain **intent and trade-offs**, not restate the code. Reserve them for architecture, algorithms, non-obvious logic, and how to use an interface; do not narrate line by line.
- Exceptions follow one rule: `std::logic_error` when the input C program is invalid, `std::runtime_error` when the environment fails (file I/O, unknown target, bad pipeline).
- Keep the front-end grammar stable unless the change is specifically a language feature. Grammar edits belong in `Parser.y`; note any new parser conflicts in [docs/ParserConflicts.md](docs/ParserConflicts.md) (`Parser.output` is regenerated by the build).

## Commit & pull request

- Write commit messages in the **imperative mood**, capitalized, ending with a period, matching the existing history — e.g. `Add tiled matrix-multiply benchmarks (M15).` Tag the milestone in parentheses when relevant.
- Keep unrelated changes out of the same commit, and avoid committing bulk `debug/` diffs your change did not intend to produce.
- Before opening a PR: rebuild, run the full suite and smoke checks above, and update any affected docs (e.g. [docs/Usage.md](docs/Usage.md) for new CLI flags).
- Describe **what** changed and **why** in the PR, and confirm CI passes on Ubuntu 24.04 / 26.04 and macOS.

## Scope

`lcc` is intentionally a small teaching compiler. Some items are deliberately **out of scope** (custom register allocator, full loop vectorizer, new backend targets); others are **unscheduled future directions**. [docs/LearningPlan.md](docs/LearningPlan.md) indexes both — see [Out of scope](docs/LearningPlan.md#out-of-scope-all-milestones) and [Future directions](docs/LearningPlan.md#future-directions-no-milestones). Please check there before starting large work, and feel free to open an issue to discuss first.
